# RuliManager v0.7 (MFC, Visual Studio 2022)

- 버전: 0.7 — 창 제목 "RuliManager v0.7", 파일 버전 정보 0.7.0.0 (`RuliManager\Version.h` 에서 관리 — 아래 빌드 3번 참고)

## 빌드
1. Visual Studio Installer에서 **"C++를 사용한 데스크톱 개발"** + **"최신 v143 빌드 도구용 C++ MFC"** 구성 요소 설치
2. `RuliManager.sln` 열기 → 구성 `Debug|x64` 또는 `Release|x64` → 빌드(Ctrl+Shift+B) → 실행(F5) — 실행 파일 이름은 `RuliManager.exe` (폴더 `D:\Project\RuliManager`, 예전 이름 VideoManager 에서 바꿈. 기존 데이터를 그대로 쓰도록 내부 저장 이름 — 설정 레지스트리 키 · %APPDATA%/%LOCALAPPDATA% 폴더 · DB 암호화 키 — 는 VideoManager 그대로)
3. **버전 관리**: 버전은 `RuliManager\Version.h` 에서만 고침 — `APP_VERSION_MAJOR/MINOR/PATCH/BUILD`(숫자) 와 `APP_VERSION_STR`(문자열, 예 "0.1")을 같이 맞추면 창 제목("RuliManager v0.1" — `OnInitDialog` 에서 설정, 리소스 CAPTION 에는 버전 없음)과 실행 파일 속성(VERSIONINFO 의 FILEVERSION · PRODUCTVERSION · FileVersion · ProductVersion)에 함께 반영. 리소스 편집기에서 버전 정보를 직접 고치면 매크로가 숫자로 바뀔 수 있으니 이 파일에서만 수정 (rc 에서는 `#include "Version.h"` — TEXTINCLUDE 2 에도 넣어 리소스 편집기로 저장해도 유지)

## README 작성 규칙
- 이 README 는 **버전 기준**으로 정리: 기능 · 변경은 그 기능이 들어간 버전 섹션(`## v0.x`)에 적고, 최신 버전이 맨 위
- 지금 버전(`Version.h` 의 `APP_VERSION_STR`)에서 추가 · 변경한 내용은 그 버전 섹션에 추가, 버전을 올리면 새 섹션을 위에 만듦
- 예전 버전 기능을 고친 경우: 새 버전 섹션에 "변경" 으로 적고, 예전 섹션의 해당 항목에도 바뀐 내용을 반영 (예전 섹션은 지금 동작 기준 설명)
- 빌드(맨 위) · 화면 · 데이터 저장 위치 · 참고(맨 아래)는 버전과 관계없는 공통 내용

[장르숨김] 으로 돌아가면 칩 줄을 숨기고 고른 장르도 풀림 (`CGenreChipBar` - TagChipCtrl, `IDC_GENRE_HIDE` / `IDC_GENRE_ALL` / `IDC_GENRE_CHIPS`, `UpdateGenreBar`)

- **배우 고유 번호 (0.6~)**: 배우마다 고유 번호(int, 1 ~ 99999999, DB 에는 8자리 `00000001`, A 줄 21번째 칸) — 이름이 바뀌어도 그대로, 지운 배우 번호는 다시 쓰지 않음(DB `#ActorIdNext<탭>다음번호` 줄). DB 의 영상 배우 칸은 이름 대신 번호로 저장: 배우 = `#00000001`, 참여 별칭 = `#00000001:과거이름` (등록 안 된 이름은 그대로 글자). 읽을 때 번호 → 지금 대표 이름(참여 별칭은 과거이름)으로 바꾸므로 프로그램 안에서는 지금처럼 이름으로 다룸, 없는 번호(지운 배우)는 뺌. 새 배우는 저장할 때 번호 부여. **0.6 변환**(0.6 전 DB): 영상에만 있는 배우 이름도 배우 목록에 등록 → 배우 목록 순서대로 1 부터 번호 → 저장하면 영상 배우 칸이 번호로 바뀜 (변환 전 원본은 DbBackup 에 백업). 주의: 0.6 DB 는 0.5 이하 프로그램에서 배우가 번호로 보임. 배우 관리 창 사진 아래(왼쪽 정렬)에 `(00000001)` 처럼 그 배우의 고유 번호 표시 (번호가 아직 없는 새 배우는 고를 때 바로 부여)
- **배우 관리 목록 정렬**: 처음 열면 이름 오름차순, 머리글(이름 · 성별 · 나이 · 생년월일 · 국적 · 키 · 데뷔일 · 은퇴일 · 별점 · 출연)을 누르면 그 열로 오름차순 → 다시 누르면 내림차순 (정렬 열 머리글에 ▲ / ▼). 이름은 첫 글자 종류로 묶어 **한글 → 영문 · 숫자 → 일본어(가나 · 한자) → 기타** 순(앞 공백 · 기호 건너뜀), 묶음 안에서 한글 · 영문은 탐색기식 자연 정렬, 일본어는 일본어 기준(ja-JP, 가나 오십음 · 한자 — 예전에는 한국어 기준이라 한자 이름이 한글 독음 순으로 한글 사이에 섞였음, 배우 선택 창 목록도 같은 순서). 나이 · 키 · 별점 · 출연은 숫자로, 나머지는 글자(숫자 자연 정렬)로 비교, 빈 값은 방향과 관계없이 뒤, 같은 값은 이름순. 검색 · 새 배우 · 저장 후 다시 채울 때도 고른 정렬 유지 (편집 중인 내용은 정렬 전에 반영)

- **하나만 실행**: 프로그램이 이미 실행 중이면 새로 실행하지 않고 기존 창을 앞으로 가져옴(최소화되어 있으면 복원) — 이름 있는 뮤텍스(`Local\RuliManager.SingleInstance.{…}`)로 확인, 기존 창은 제목 "RuliManager v…" 로 찾음(못 찾으면 "이미 실행 중" 안내). 같은 DB · 이미지 캐시를 두 프로그램이 동시에 쓰지 않도록
- **폴더 추가/제거/새로고침**: 하위 폴더까지 동영상 검색 (mp4, mkv, avi, wmv, mov, webm, ts 등). 새로 찾은 파일은 **임시 목록**(`pending.tsv`)에 기록되고 격자에 "● 임시"로 표시 → 영상 정보를 저장([저장] 또는 정보 수정 후 다른 영상 선택)하면 정식 DB(`library.tsv`)에 등록
- **이동식 디스크 폴더**: [폴더 추가] 때 "이동식 디스크(USB 메모리 · 외장 하드 등)에 있습니까?" 를 물어 [예]면 이동식으로 등록(이동식 드라이브면 [예]가 기본, 같은 폴더를 다시 추가하면 바꿀 수 있음, library DB `F` 줄에 `R` · 볼륨 일련번호 · 볼륨 이름 추가). 이동식 폴더의 영상은: 디스크가 연결되지 않았거나 같은 드라이브 문자에 다른 디스크(일련번호가 다름)가 연결되어 있으면 시작 · 새로고침 때 지우지도 스캔하지도 다른 파일에 다시 연결하지도 않음(정보 그대로 보관) · 드라이브 문자가 바뀌면(E: → F:) 같은 일련번호의 디스크를 찾아 폴더와 영상 경로를 새 문자로 바꿈(시작 · 새로고침 · 디스크를 꽂을 때 — `WM_DEVICECHANGE`) · 영상 카드 이미지 왼쪽 아래에 "이동식 디스크"(주황, 연결 안 됐으면 회색 "이동식 디스크 (연결 안 됨)") 표시. [폴더 제거] 목록에는 "[이동식 디스크]" / "[이동식 디스크 - 연결 안 됨]" 표시
- **이동식 디스크 영상의 커버 캐시 / 커버 DB**: 이동식 폴더 영상의 커버 이미지는 처음 읽을 때 캐시(`<실행 폴더>\cache\covers\<키 해시>.jpg`, 긴 변 640px 이하 JPEG — 키 = 볼륨 일련번호 + 드라이브 문자를 뺀 경로라 문자가 바뀌어도 같음)에 보관하고, 커버 전용 DB `covers.vmdb`("VMDB-CVRS1" + 암호화된 묶음) 하나로 묶음 — 기동 때 캐시로 풀고, [DB 반영] · 종료 때 새 커버가 있으면 지금 이동식 영상의 것만 다시 묶음(지운 영상의 커버는 빠짐, 종료 때 저장에 성공하면 캐시 폴더 삭제, 못 풀면 덮어쓰지 않음). 디스크가 연결되지 않았으면 카드에는 캐시의 커버를 **반투명**으로, 상세 미리보기에도 이미지(캐시의 커버면 "이미지: 커버 캐시 (이동식 디스크 연결 안 됨)")를 **반투명**으로 표시(SFW 모자이크도 적용, `CImagePreview::SetDimmed` — 이미지를 바꾸면 다시 불투명)
- **연결 안 된 이동식 디스크 영상은 보기 전용**: 영상 카드 / 목록 오른쪽 클릭 메뉴에서 [DB에서 삭제 (파일 유지)] 말고는 비활성(재생 · 탐색기 · 텍스트로 정보 입력 · 웹페이지 붙여넣기), 상세 화면은 모든 칸 · 별점 · 물방울 · 칩 · 선택 버튼 · 이미지 변경/검색 · 끌어다 놓기 · 제작사 카드(변경 · ×)를 막고 파일 이름 줄에 "[이동식 디스크 연결 안 됨 - 수정 불가]" 표시(저장도 하지 않음). 더블클릭 · Enter · Space(재생)도 아무 동작 안 함(메시지 없음). 디스크를 꽂거나 빼면 상세의 수정 가능 여부를 바로 다시 적용
- **이동식 디스크 영상의 해상도 · 재생 시간**: 연결 안 된 동안에는 카드 · 상세 모두 읽지 않고 표시도 하지 않음(전에 읽어 둔 값도 숨김, 실패를 기억하지 않음). 디스크를 꽂으면(`DBT_DEVICEARRIVAL`) 읽지 못했던 결과(카드 `m_cardMedia`, 상세 `CMediaInfoLabel` 캐시)를 지우고 다시 읽어 표시 (`ForgetFailedMediaInfo`)
  - **영상 폴더 텍스트 → 영상 정보**: 스캔 · 새로고침으로 새 영상을 찾을 때(임시 항목), [재 스캔] 때는 저장된 영상도, 영상 폴더의 txt(상위 폴더 이름 기준 `ABC-123\ABC-123.txt` → 폴더 이름의 '_' 왼쪽이 같은 txt → 같은 이름 `ABC-123.txt` / `ABC-123.mp4.txt` → '_' 왼쪽이 같은 이름 → 폴더에 영상과 txt 가 하나씩이면 그 파일, 배우 정보 파일 제외)에서 `항목: 값` 을 읽어 비어 있는 칸만 채운 뒤 남은 빈칸은 폴더 구조로. 인식 항목: 제목/title/タイトル, 발매일/출시일/release/発売日/配信開始日, 별점/rating(숫자 또는 ★), 배우/출연/cast/出演者/女優(여러 명 → 별칭이면 배우 이름 + 참여 별칭으로, `한글이름, (English Name, なまえ)` 처럼 괄호 앞에 쉼표가 있어도 한 사람으로 읽음. 등록 배우 이름 · 별칭과 언어 단위(한글 / 영어 / 일어 — 괄호 앞 이름, 괄호 안 각 이름)로 같은 언어끼리 비교해서 한 언어라도 같으면 다른 언어 이름은 보지 않고 그 배우로 연결 — 공백 · 대소문자 무시, 영어는 단어 순서도 무시(Hikaru Nagi = Nagi Hikaru), 여러 배우가 걸리면 한글 → 일어 → 영어 순으로 맞은 배우, 같은 배우로 연결된 이름이 여러 개면 하나로). 이 언어 단위 비교는 폴더 구조로 정하는 배우(폴더 이름 `나기 히카루` → 배우 `나기 히카루(Hikaru Nagi, 凪ひかる)`), 영상 배우 칸 정리, 새 배우 추가 판단에도 똑같이 적용. 시작 · 스캔 때 사진 · 정보 · 별칭 · 별점 · 즐겨찾기가 하나도 없는 배우가 다른 배우와 언어 단위 이름이 같으면 그 배우로 합침(영상의 배우 표기도 바꿈). 별칭도 언어 단위로 비교 — 배우 관리 창 저장 · 배우 폴더 txt 의 다른 이름 추가 때 대표 이름이나 이미 있는 별칭과 한글 / 영어 / 일어 이름 중 하나라도 같으면 넣지 않음(예: `나기 히카루(Hikaru Nagi, 凪ひかる)` 의 별칭 `나기 히카루(凪ひかる)` 는 무시). 시작 · 스캔 때 이미 들어가 있는 그런 별칭도 빼고 영상의 참여 별칭에서도 정리, 스튜디오/제작사/메이커/maker/label/メーカー, 태그/장르/genre/ジャンル, 물방울. 메모/설명/줄거리/plot/内容 항목은 무시(영상 메모 기능 삭제). 목록은 쉼표 · 、 · / · | · # 로 구분(태그는 / 로 나누지 않음 — "OL/사무원" 같은 태그 그대로). 스튜디오 · 태그가 목록에 이미 있으면 목록의 표기(대소문자)로 맞추고, 없으면 스튜디오 / 태그 목록에 새로 추가. - **[정보 txt 생성]** (하단, [DB 반영] 오른쪽): 확인 후 저장된 영상마다 같은 폴더에 `영상이름.txt`(파일 · 제목 · 발매일 · 별점 · 배우 · 참여 별칭 · 스튜디오 · 태그 · 물방울), 배우 폴더가 있는 배우마다 배우 폴더에 `배우폴더이름.txt`(이름 · 다른이름 #… · 성별 · 생년월일 · 국적 · 키 · 치수 · 컵 · 데뷔 · 은퇴 · 별점 · 즐겨찾기 · 메모)를 UTF-8 `항목: 값` 형식으로 만듦. 같은 이름이 있으면 덮어쓰고 내용이 같으면 그대로 둠. 배우 txt 는 배우 폴더 텍스트 읽기 형식과 같아서 다시 읽어 들일 수 있음(다른이름은 읽을 때 뒤집히므로 거꾸로 기록), 영상 txt 는 첫 줄 `# RuliManager 영상 정보` 로 구분해 배우 정보로 읽지 않음
- **배우 폴더 텍스트 → 배우 정보**: 새 배우를 추가할 때, 그리고 배우 정보(생년월일·키·국적·데뷔·은퇴·치수·컵)가 모두 비어 있는 배우는 배우 폴더 바로 아래의 텍스트 파일(*.txt — 폴더/배우 이름 · profile · info · actor · 프로필 · 정보 이름 우선)에서 `항목: 값` 줄을 읽어 비어 있는 칸만 채움. 인식 항목(한국어·영어·일본어): 생년월일/생일/birthday/生年月日, 키/신장/height/身長, 치수/쓰리사이즈/measurements/スリーサイズ(B105 W59 H88 · 105-59-88 · B105(I)), 가슴/허리/엉덩이(bust/waist/hip), 컵/cup/カップ, 국적/출신/nationality/国籍(일본·Japan·日本·JP → 일본), 성별/gender, 데뷔/debut/デビュー, 은퇴/retire/引退, 별칭/다른이름/aka/別名(쉼표 · 、 · / · # 로 나눠 여러 개 → 파일에 적힌 순서의 반대로 별칭에 추가. 배우 이름과 같은 이름 — 전체 이름, 괄호 앞 이름, 괄호 안 각 이름(공백·대소문자 무시) — 과 이미 있는 별칭은 추가 안 함), 메모/memo/bio. 구분자는 `:` `：` `=` 탭, 날짜는 1998-02-17 · 1998.2.17 · 1998년 2월 17일 · 19980217, 인코딩은 UTF-8 · UTF-16 · ANSI(CP949) 자동
- **[재 스캔]** ([새로고침] 오른쪽): 새로고침과 같은 폴더 스캔 + 이미 DB 에 저장된 영상에도 폴더 구조를 다시 적용해 비어 있는 배우 · 스튜디오 · 발매일을 채움(값이 있는 칸은 그대로). 새로 찾은 배우는 배우 폴더의 사진 · 텍스트 정보까지 반영
- **폴더 구조 자동 인식** (등록 폴더 기준, 영상 파일은 각자 영상 폴더 안): `폴더\영상\영상.mp4` → 영상만 / `폴더\배우\영상\영상.mp4` → 배우 지정 / `폴더\스튜디오\배우\영상\영상.mp4` → 스튜디오 · 배우 지정 (더 깊으면 위 두 단계 폴더 사용, 등록 폴더 바로 아래 영상 파일은 영상만). 영상 파일 이름이나 영상 폴더 이름에 `[2024.05.01]` / `[20240501]` 이 있으면 발매일로 지정(파일 이름 우선). 찾은 배우·스튜디오는 각 목록에 자동 추가. 새 배우를 추가할 때, 그리고 이미 등록된 배우 중 사진이 없는(사진 파일이 없어진) 배우도(시작 · 스캔 · 새로고침 때, 배우 이름이나 별칭과 같은 폴더) 배우 폴더(`폴더\배우\`) 바로 아래에 이미지 파일이 있으면 배우 사진으로 지정(폴더/배우 이름 · folder · poster · profile · cover · actor 이름 우선, 없으면 이름 순 첫 번째, 이미지 캐시 actors 에 사본). 새로 찾은 임시 항목에만 적용되며, 이미 DB에 저장된 영상의 정보는 바꾸지 않음

- **배우 칩**: 상세 정보의 배우도 태그처럼 칩 `[이름 ×]` 로 표시 — [별칭] 줄을 합쳐서 칩에는 이 작품에서 고른 별칭(없으면 대표 이름) 하나만 표시, 칩을 오른쪽 클릭하면 그 배우의 별칭 중에서 고름(예전 왼쪽 클릭 → 오른쪽 클릭으로 바꿈, 왼쪽 클릭은 메뉴 없음 · 더블클릭은 배우로 이동)(고른 값이 이 작품의 별칭, 체크된 별칭을 다시 고르면 해제). 마지막으로 고른 별칭은 배우마다 기억해서, 다른 영상에 그 배우를 새로 넣으면(칩 입력·배우 선택 창) 그 별칭이 초기값으로 들어감, × 삭제 / 오른쪽 × 모두 지우기 / ⌄ 배우 선택 창. 입력 칸에 글자를 넣으면 배우 이름·별칭 자동 완성(↓ 전체), Enter / 쉼표 / 목록 선택으로 추가 (별칭으로 고르면 저장 시 배우 이름 + 참여 별칭으로 정리)
- **태그 칩**: 오른쪽 클릭 메뉴 [태그 관리...] — 태그 관리 창을 엶(오른쪽 클릭한 칩이 있으면 그 태그를 선택해서, 입력 칸 위는 입력 칸 자체 메뉴, `CTagChipCtrl::ChipAt`). 칩에 마우스를 올리면 칩 위(공간이 없으면 아래)에 그 태그 카드 팝업 — 태그 탭 카드와 같은 모양(꼬리표 아이콘 · "이름 (영어, 일본어)" · ▶ 영상 수 · 즐겨찾기 하트), 포커스를 가져가지 않고 마우스도 통과, 칩에서 벗어나면 닫힘 (`CCardPopup`, `m_onChipHover`). **배우 칩**도 마우스를 올리면 그 배우 카드 팝업 — 배우 탭 카드와 같은 모양(사진 · 별점 리본 · 즐겨찾기 하트 · 국기 · 성별 + 이름 · 나이 — 아래 구분선 + 출연 수 영역은 뺌, 크기는 지금 확대 단계의 배우 카드 크기, `DrawActorCardFor`), DB 에 없는 배우 이름이면 표시 안 함, 칩을 눌러 메뉴를 열면 닫힘. 칩 오른쪽 × 에 마우스를 올리면 빨간 동그라미 바탕 + 흰 × 로 표시(태그 · 배우 · 제작사 등 칩 입력 공통). 상세 정보의 태그는 칩 형태 `[태그 ×] [태그 ×] … ×  ⌄` 로 표시(가나다 순 — 새로 넣은 태그도 순서 자리로 들어가고 저장도 그 순서, `SortTagsKo` / `StrCmpLogicalW`) — 칩의 × 로 삭제, 오른쪽 × 는 모두 지우기, ⌄ 는 태그 목록에서 선택. 칩 뒤 입력 칸에 글자를 넣으면 태그 목록에서 자동 완성(↓ 전체 목록), Enter / 쉼표 / 목록 선택으로 추가, 빈 칸에서 Backspace 는 마지막 태그 삭제. 칩이 넘치면 여러 줄로 늘어남
- **자동 완성 입력**: 상세 정보의 배우 · 별칭 · 스튜디오 · 태그 칸에 글자를 입력하면 DB(배우·별칭·스튜디오·태그 목록)에서 실시간으로 찾아 콤보박스처럼 아래에 목록 표시 → 마우스 클릭 또는 ↑/↓ + Enter(Tab)로 선택, Esc 닫기, 빈 칸에서 ↓ 는 전체 목록. 배우·별칭·태그는 쉼표로 여러 개(커서가 있는 값만 완성, 이미 입력한 값은 제외). 배우 칸에서 별칭을 고르면 저장 시 배우 이름 + 참여 별칭으로 정리, 별칭 칸에서 다른 배우의 별칭을 고르면 그 배우가 배우 칸에도 추가됨. 목록에 없는 값을 직접 입력해 저장하면 각 목록에 새로 추가
- **참여 별칭**: 상세 정보의 배우 아래 [별칭] — 이 작품에서 배우가 쓴 별칭. [선택...] → 지정된 배우들의 별칭 메뉴에서 체크/해제. 배우 칸에 별칭으로 적힌 배우(폴더 스캔 등)는 자동으로 본래 배우 이름 + 참여 별칭으로 정리되고, 배우를 빼면 그 배우의 참여 별칭도 함께 빠짐. 검색에도 포함
- **물방울 카운트**: 영상 상세 정보의 별점 오른쪽 `💧 0` — 클릭할 때마다 1 증가, 오른쪽 클릭 → [초기화] 로 0. 1 이상이면 영상 카드 아래 개수 줄(태그 수 · 배우 수 옆)에도 물방울 + 숫자 표시. 별점처럼 바로 저장 (library.tsv V 줄 13번째 칸, `DropCounter.h`, 아이콘 `VectorIcon::Drops`)
- **재생 시간 / fps / 해상도**: 영상 상세 정보의 파일 이름 줄 오른쪽([이미지 검색][이미지 변경] 버튼 위)에 `123분 | fps: 29.97 | 1080p` 표시 (재생 시간 · fps 회색, 해상도 흰색 굵게, 재생 시간은 분 단위 반올림 — 1분 미만은 1분, Windows 속성 "길이"(PKEY_Media_Duration), 칸 폭은 최대 버튼 3개 폭). 속성에 해상도 · fps · 재생 시간이 없으면(속성 처리기가 없는 MKV · AVI 등) Media Foundation 으로 파일을 직접 열어 영상 스트림의 크기(MF_MT_FRAME_SIZE) · fps(MF_MT_FRAME_RATE) · 전체 길이(MF_PD_DURATION)를 읽음 — 영상 카드의 해상도 · 재생 시간도 같음 (`CMediaInfoLabel::ReadInfo`). 값은 Windows 파일 속성(프레임 속도 · 프레임 너비/높이)에서 읽고 경로별로 기억. 해상도는 16:9 기준 높이로 1080p · 2160p 등 표준 이름 (`MediaInfoLabel.h`). Windows 가 속성을 읽지 못하는 형식(코덱/속성 처리기 없음)은 표시 안 함
- **영상 카드 해상도 · 재생 시간**: 영상 카드 이미지 오른쪽 아래에 재생 시간 `2:03:15` (바탕 없이 글자 뒤 1px 검은 그림자, 시:분:초 보통 글꼴 — 해상도는 품번 줄의 해상도 마크로 옮겨 이미지 안에서는 표시 안 함). 값은 상세 정보와 같은 Windows 파일 속성 — 처음 화면에 나올 때 백그라운드 스레드(하나)가 읽어서 경로별로 보관(`CardMediaInfo` / `m_cardMedia`, 프로그램을 켜 있는 동안 — 창을 닫을 때 스레드를 멈추고 끝날 때까지 기다린 뒤 대기열 · 남은 결과 메시지 정리, `StopCardMediaThread`), 읽는 동안에는 표시 없이 그리고 다 읽으면 다시 그림. 영상 카드 이미지 위에 마우스를 올리면 이미지만 보임(오른쪽 위 로고 · 왼쪽 위 별점 리본 · 오른쪽 아래 해상도 / 재생 시간이 약 0.12초 동안 부드럽게 사라지고, 마우스를 치우면 부드럽게 다시 나타남 — 15ms 타이머로 불투명도를 조금씩 바꿔 AlphaBlend, 바뀌는 카드만 다시 그림, `m_overlayFade`, `GridHoverZone`, 클릭 · 더블클릭 동작은 그대로). 영상 카드의 제목 3줄 칸에 마우스를 올렸을 때 제목이 3줄을 넘어 "…" 로 잘려 있으면 풍선 도움말로 제목 전체 표시(긴 제목은 여러 줄, `GridTipText`) 설정 창 [표시] → "영상 카드 이미지 오른쪽 아래에 해상도 · 재생 시간 표시" 체크로 켜고 끔(기본 켬, 레지스트리 Settings\CardMediaInfo) — 끄면 파일 정보를 읽지도 그리지도 않아 영상이 많을 때 처음 로딩이 빨라짐(끌 때 읽는 중이던 대기열은 멈추고, 이미 읽은 정보는 남겨 둬서 다시 켜면 바로 표시). 영상 상세 정보의 재생 시간 / fps / 해상도는 설정과 관계없이 표시
- **영상 카드 해상도 마크**: 카드 품번 줄 오른쪽 끝에 플랫 배지(각진 사각형, 품번 글자색 `kTextColor` + 카드 배경색 `kCardBack`): 품번색 테두리 안 왼쪽 카드 배경색 칸에 해상도(품번색 굵은 글자) + 오른쪽 품번색 칸에 등급(카드 배경색 굵은 글자) — 예) `[1080p|FHD]`. 16:9 기준 높이(가로가 넓으면 가로×9/16, 세로 영상은 가로·세로를 바꿔 계산)로 `480p 등|SD`(720 미만, **연회색** 배지) · `720p|HD` · `1080p|FHD` · `1440p|QHD` · `4K|UHD`(2160) · `8K|UHD`(4320) (`CMediaInfoLabel::GradeText`). 품번(+ 파일 순번)은 마크 왼쪽까지만 그림, 카드가 아주 좁으면 생략. 해상도 · 재생 시간 표시 설정을 끄거나, 정보를 아직 못 읽었거나, 이동식 디스크가 연결 안 됐으면 표시 안 함
- **스크롤 성능**: 격자(영상 · 배우 · 제작사 · 태그 공통 `CVideoGrid`)는 스크롤할 때 이미 그려진 부분을 옮기고(`ScrollWindowEx`) 새로 드러난 줄만 다시 그림, 마우스 오버가 바뀌면 그 카드 두 장만 다시 그림. 영상 카드의 오른쪽 위 로고는 카드 크기로 줄이고 75% 불투명을 적용한 사본을 보관(`m_logoMarks`), 제목 3줄 줄바꿈 결과도 제목 · 폭별로 보관(`m_titleLines`)해서 스크롤 중에는 다시 계산하지 않음
- **성별**: 미지정 / 여성 / 남성 / 트랜스젠더 여성 / 트랜스젠더 남성 / 인터섹스 / 논바이너리 (배우 관리 창 콤보). 카드의 성별 기호: ♀ 분홍 · ♂ 파랑 · ⚧ 연분홍(트랜스젠더 여성) · ⚧ 하늘색(트랜스젠더 남성) · ⚥ 노랑(인터섹스) · ⚲ 보라(논바이너리) — 글꼴에 없는 기호는 대체 글꼴로. 사진이 없을 때 기본 이미지: 여성 · 트랜스젠더 여성 = 여성 실루엣, 남성 · 트랜스젠더 남성 = 남성 실루엣, 그 외 = 흰 사람. 배우 txt 의 성별은 Female / Male / Transgender Female · MTF / Transgender Male · FTM / Intersex / Non-Binary(영어 · 한글 · 일어)를 인식

- **영상 웹페이지 붙여넣기 "출연" 배우 연결 · 이름 조립**: 붙여넣은 출연 배우 중 지금 영상 배우와 같은 배우로 판단되지 않는 것이 있으면(지금 영상에 배우가 있을 때) [읽어낸 정보 확인] 전에 **출연 배우 연결** 창 (왼쪽 = 붙여넣은 출연 그대로의 이름, 오른쪽 = 지금 배우 — 과거 이름으로 참여했으면 그 과거 이름). 같은 배우(등록 배우 · 다른 이름 · 언어 단위 이름)는 처음부터 연결, 연결 안 된 왼쪽 = 처음 "추가"(↔ 무시), 연결 안 된 오른쪽 = 처음 "지움"(↔ 유지). 취소하면 붙여넣기 전체 취소. 연결된 배우(자동 · 직접)와 등록 배우로 판단된 추가 배우는 **기존 이름 + 붙여넣은 이름을 조립**해 `한글이름(영어이름, 일본어이름)` 형태로 — 언어(한글 / 영어 / 일어)마다 기존 표기 우선, 없는 언어만 붙여넣은 이름에서 채움(한글이 없으면 영어, 그것도 없으면 일본어가 앞 이름). 기존 이름이 대표 이름이면 배우 이름 변경(모든 영상의 배우 표기도), 과거 이름이면 그 다른 이름과 모든 영상의 참여 별칭을 조립한 이름으로 바꿈. 다른 배우가 이미 그 이름을 쓰거나 더할 언어가 없거나 언어를 가를 수 없는 조각이 있으면 그대로. 바뀐 배우 목록은 바로 저장

- **스크린샷 추출**: 영상 카드 / 목록 오른쪽 클릭 [스크린샷 추출...] → 찍을 장수 N 입력(1~100, 마지막 값 기억 Settings\ShotCount, 기본 8). 재생 시간을 N+2 칸으로 나눠 **맨 앞 · 맨 뒤 칸은 버리고** 가운데 N 칸마다 칸 시작 시간에서 한 장(예: 3장 · 100분 → 20 · 40 · 60분). 그 장면에서 **Windows 얼굴 인식**(`Windows.Media.FaceAnalysis.FaceDetector`)으로 얼굴을 못 찾으면 10초씩 뒤로 다시 찍어 봄(`kRetryStep`)(그 칸이 끝나기 전까지), 끝까지 못 찾으면 칸 시작 장면을 저장. 저장 = `<영상 폴더>\Screenshot\<영상 이름>_01.jpg` …(같은 규칙의 예전 `<영상 이름>_숫자.jpg` 는 먼저 지움, 원본 해상도 JPEG). **대기열 방식** — 추출 중에도 다른 영상을 넣으면 대기열 맨 뒤에(이미 추출 중 · 대기 중인 영상은 안내만), 백그라운드 스레드 하나로 넣은 순서대로 하나씩(`m_shotQueue` · `StartNextShot`, 프로그램을 닫으면 남은 대기열은 버림). 창 제목에 "스크린샷 추출 중 (2 / 8) · 대기 3" + 추출 중인 영상 카드 전체의 왼쪽 아래에 "(2/8)"(파란 테두리), 대기 중인 영상 카드에는 "(대기 1)"(회색) 표시 — 대기 표시를 더블클릭하면 대기열에서 뺌, **추출 중 표시를 더블클릭하면 그 영상만 멈춤**(지금 장면이 끝나면 멈추고 그때까지 저장한 것은 남김, 다음 대기 영상으로, `GridDblClick` · `ShotBadgeRect`), 끝나면 스크린샷 격자 갱신(완료 알림 창은 없음, 영상을 열지 못했을 때만 알림), 창을 닫으면 멈춤), 연결 안 된 이동식 디스크 영상은 메뉴 비활성. 영상 읽기 = Media Foundation(키프레임으로 이동 후 목표 시간까지 디코딩, RGB32), 얼굴 인식은 회색조 · 긴 변 1280 으로 줄여서. `ScreenshotExtractor.cpp` 는 C++/WinRT 를 쓰므로 **미리 컴파일된 헤더 없이 C++20** 으로 빌드(프로젝트 파일에 파일별 설정, `windowsapp.lib`)
- **분할 파일 (같은 정보 사용)**: 같은 폴더에서 파일 이름의 마지막 '_' 왼쪽이 같고 오른쪽이 숫자인 파일(`ABC-123_1.mp4`, `ABC-123_2.mp4`, 순번 없는 `ABC-123.mp4` 포함)은 한 묶음 — 카드는 파일 수만큼 표시(품번 오른쪽 `(1/3)`)하지만 품번 · 제목 · 별점 · 물방울 · 발매일 · 배우(참여 별칭) · 스튜디오 · 태그는 같이 사용. 한 파일에서 저장하면(별점 · 물방울 클릭 포함) 묶음 전체에 복사되고 임시 파일도 함께 등록. 시작할 때와 스캔으로 새 파일을 찾았을 때 묶음마다 빈 정보를 등록된 파일(이름 순 첫 파일 우선)의 값으로 채움(이미 들어 있는 값은 덮어쓰지 않음, 등록된 파일이 있으면 임시 파일도 등록). 이미지 변경은 순번을 뗀 이름(`ABC-123.jpg`)으로 저장하고 파일별 이미지(`ABC-123_2.jpg`)는 휴지통으로 → 묶음 전체가 같은 이미지. DB 형식은 그대로(파일마다 줄이 있고 값만 같게 유지)
- **품번**: 영상 상세 정보의 제목 위 [품번] 칸(폭 1/3 — 오른쪽에 품번 접두어가 제작사 · 레이블의 시리즈(품번)와 같으면 그 시리즈의 라벨명 표시, `SeriesInfoForCode`)(검색 대상, [이미지 검색] 기본 검색어). 비어 있으면 파일 이름 → 영상 폴더 이름에서 자동으로 찾음(영문 2~6자 + -/_/공백 + 숫자 2~5자 → `ABC-123` 대문자, 시작 · 스캔 · 재 스캔 때). 영상 txt 의 품번/code/品番 항목도 읽고, [정보 txt 생성]에도 기록 (library.tsv V 줄 14번째 칸)
- **출연 배우 카드**: 영상 상세 정보의 태그 아래에 이 영상의 배우를 작은 세로 카드(사진 3:4 · 별점 리본 · 즐겨찾기 하트 · 이름 / 괄호 안 이름 또는 나이)로 가로 한 줄 표시. 넘치면 휠 · 아래 스크롤바로 이동, 마우스를 올리면 전체 이름 툴팁, 더블클릭하면 배우 탭에서 그 배우 선택. 사진 오른쪽 아래 국기, 오른쪽 위 하트로 즐겨찾기 지정/해제(마우스를 하트 자리에 올리면 반투명 회색 하트, 클릭하면 바로 저장). 배우 칸을 바꾸면 바로 갱신 (`ActorStrip.h`)
- **제목·별점·발매일·배우·스튜디오·태그**: 오른쪽 아래 패널에서 편집. 상세보기의 글자 컨트롤(라벨 · 파일 이름 · 이미지 줄 · 품번 · 제목 · 발매일 · 배우/스튜디오/태그 칩)은 기본 글꼴보다 1pt 크게(줄 높이 · 라벨 폭도 맞춤, `ApplyDetailFonts`). 제목 칸은 여러 줄 에디트(자동 줄바꿈, 글꼴 4줄 높이, Enter = 저장, 붙여 넣은 줄바꿈은 공백으로 저장). 영상 메모 기능은 삭제(메모 칸 없음 → 그만큼 이미지가 커짐, 예전 메모는 읽지 않고 다음 저장 때 지워짐) (발매일은 체크를 해제하면 "없음"), 다른 항목 선택 시 자동 저장
- **파일 작업**: 이름 변경(F2 키만, 버튼·오른쪽 클릭 메뉴는 없음), [DB 삭제 (Del)] = 선택한 영상의 DB 정보만 삭제(파일은 유지, 저장된 영상은 임시 항목으로 돌아감 / 임시 항목은 목록에서 빠지고 다음 스캔 때 다시 나타남 / 파일이 없으면 목록에서 제거), 탐색기에서 보기, 기본 플레이어로 열기, 오른쪽 클릭 메뉴

## 데이터 저장 위치
DB 는 실행 파일 폴더의 `library.vmdb` (정보: 영상·배우·스튜디오·태그 + 임시 목록, 암호화) 와 `images.vmdb` (이미지 DB: 배우 사진 · 스튜디오 이미지 전체를 암호화해서 한 파일로, 태그는 이미지 없음) 두 파일. 이 두 파일만 옮기면 다른 PC 에서도 그대로 동작 (실행 파일 폴더에 쓸 수 없으면(Program Files 등) `%APPDATA%\VideoManager`, 예전 위치 %APPDATA% 의 library.vmdb 는 처음 실행 때 실행 파일 폴더로 복사하고 .bak 으로 남김). 하단 [DB 폴더 열기] 버튼으로 탐색기에서 바로 열기
- **작업 DB (반영 방식)**: 실행하면 `library.vmdb` 를 `library.work.vmdb` 로 복사해서 사용하고, 실행 중 저장(별점·정보 저장·배우/태그 편집 등)은 작업 DB 에만 씀. 하단 [DB 반영] 버튼(반영 안 한 정보 변경이나 이미지 DB 에 저장 안 한 이미지 변경 — 등록 · 정리 — 이 있을 때만 활성, 초록색) 또는 종료할 때 작업 DB 를 원본에 원자적으로 반영(임시 파일에 복사 후 교체)하고, 종료 시 작업 DB 삭제. 반영에 실패하면 종료할지 물어봄. 비정상 종료로 작업 DB 가 남아 있고 원본과 다르면 다음 실행 때 [예] 반영 / [아니요] 버리기 선택. 이미지는 이미지 캐시에 바로 저장되고 [DB 반영] / 종료 때 images.vmdb 로 묶임
- **시작 시 DB 백업**: 프로그램을 켤 때마다 불러오기 전에 `library.vmdb` 와 `images.vmdb` 를 DB 폴더의 `backup` 폴더에 `library_YYYYMMDD_HHMMSS.vmdb` / `images_YYYYMMDD_HHMMSS.vmdb` 형식으로 복사. 가장 최근 백업과 내용이 같으면 건너뛰고, 파일마다 최근 10개만 남김. 되돌리려면 프로그램을 끄고 백업 파일을 원래 이름으로 바꿔 DB 폴더에 덮어쓰기
- **이미지 DB ↔ 이미지 캐시**: 기동할 때 `images.vmdb` 를 이미지 캐시 폴더(실행 파일 폴더의 `cache\images\actors | studios`, 평문 파일 — 예전 위치 `%LOCALAPPDATA%\VideoManager\cache\images` 에 남은 이미지는 기동 때 합치고 이미지 DB 저장에 성공하면 지움)에 풀어서 사용하고, 종료할 때 캐시 이미지 전체를 다시 `images.vmdb` 하나로 묶어(바뀐 것이 없으면 건너뜀) **저장에 성공한 경우에만** 캐시 폴더를 지움. 저장은 임시 파일에 쓰고 → 다시 읽어 풀어서 이미지 개수를 확인한 뒤 → 원자적으로 교체. 저장에 실패하면(1.5GB 초과 · 쓰기 실패 등) 이유를 알리고 종료할지 묻고, 캐시는 남겨 둠. 하단 [DB 반영] 을 누르면 이미지 변경사항도 바로 images.vmdb 에 저장(이미지만 바뀐 경우에도 버튼 활성, 상태줄에 "DB · 이미지 DB 에 반영했습니다" 등, 실패하면 이유 표시 — 캐시는 종료 때 지움). 비정상 종료로 캐시가 남아 있으면 다음 기동 때 지우지 않고 그대로 두고 images.vmdb 에서 없는 파일만 풀어 합침. images.vmdb 를 풀지 못하거나(손상) 하나라도 캐시에 쓰지 못하면 그 실행에서는 images.vmdb 를 덮어쓰지 않고 캐시도 지우지 않음. 예전 실행 폴더의 `Image` 폴더(actors / studios)는 처음 기동 때 캐시로 복사해서 쓰고, 이미지 DB 저장에 성공하면 `Image.bak` 으로 이름만 바꿈(지우지 않음). 이미지 DB 백업에서 되돌리려면 프로그램을 끄고 `backup\images_….vmdb` 를 `images.vmdb` 로 바꿔 덮어쓰기
- **등록 이미지 복사본**: 배우 사진 · 스튜디오 이미지를 등록하면 원본을 복사해서 이미지 캐시(actors / studios)에 평문 사본으로 두고 종료 때 images.vmdb 에 묶임 — 파일 이름은 `날짜-시각_원래이름.jpg`. 예전에 암호화해서 저장한 사본(`.vmimg`)은 시작할 때(DB 를 정상적으로 읽었을 때만) 평문 사본으로 풀어서 다시 연결(원래 .vmimg 은 연결이 끊겨 아래 정리 때 휴지통으로). 어디에도 연결되지 않은 캐시 파일은 시작할 때 **휴지통으로** 옮김(영구 삭제 아님, DB 를 복호화하지 못했거나 연결된 이미지가 하나도 없으면 정리하지 않음) (태그는 이미지 없음, 예전 태그 이미지 기록은 무시) → 원본을 옮기거나 지워도 이미지 유지. DB 에는 이미지 루트 기준 상대 경로(`actors\…`)로 기록
- 예전에 원본 경로로 등록된 이미지는 프로그램 시작 시 자동으로 복사본으로 교체(원본이 남아 있는 경우). 쓰이지 않게 된 복사본은 다음 시작 때 정리되고 다음 저장부터 DB 파일에서 빠짐

- DB 파일 형식/암호화: library.vmdb = "VMDB-PACK1" + [정보 묶음] + [길이 0], 정보 묶음은 AES-256-CBC(Windows CNG) 암호화 (키 = 프로그램 안 고정 문자열의 SHA-256, `DbCrypt.h`). 이미지까지 한 파일에 들어 있던 예전 library.vmdb 나 이미지 DB images.vmdb = "VMDB-IMGS1" + u64 길이 + 암호화된 묶음 { `images\<actors|studios>\<파일>` , 데이터 } (예전 한 파일 형식 library.vmdb 의 이미지 묶음은 캐시로 풀고 바로 저장해서 비움). 예전 형식(library.tsv / pending.tsv / images 폴더)은 처음 실행 때 읽어서 묶고 .bak 으로 남겨 둠. 복호화에 실패하면 경고하고 그 실행에서는 저장하지 않아 기존 DB 를 덮어쓰지 않음. 메모장으로 못 보게 하는 수준(프로그램을 분석하면 풀 수 있음), 키 문자열을 바꾸면 기존 DB 를 못 읽음
- 배우 사진 검색: 배우 관리 창 [사진 검색...] (사진 선택 버튼 아래) → 배우 풀 네임(괄호 안 영문/일본어 이름 포함, 검색 창에서 고칠 수 있음)으로 API 키 없이 이미지 검색. 검색 엔진 콤보 Bing / Yandex, [세이프서치 끄기] 체크 (둘 다 기억), 썸네일 10개(5×2, 각 칸 아래 원본 크기 · 확장자 "1280×720 · JPG", 크기를 모르면 확장자만)씩 [◀ 이전] [다음 10개 ▶] 로 넘겨 보기 (다음 결과는 필요할 때 더 받음). 클릭 후 [선택] 또는 더블클릭 → 원본을 받아(실패하면 썸네일) DB 폴더 images\actors 에 복사해서 사진으로 지정. 검색 결과 페이지를 읽는 비공식 방식이라 엔진 페이지가 바뀌면 해당 Fetch 함수를 고쳐야 할 수 있음 (`ImageSearchDlg.h`, `WebHelper.h`, WinHTTP)
- 영상 이미지 변경: 영상 탭 상세의 이미지 줄 오른쪽 [이미지 검색...] (배우 사진 검색과 같은 창, 검색어 = 제목 또는 파일 이름에서 [날짜] 등 대괄호 부분 제외) 또는 [이미지 변경...] (파일 선택) → 고른 이미지는 미리보기에 바로 표시, [저장](또는 다른 영상으로 이동해 자동 저장)하면 영상 파일과 같은 폴더에 "영상이름.확장자"(예: movie.mp4 → movie.png)로 복사. 같은 이름의 기존 이미지(다른 확장자, movie.mp4.jpg 형식 포함)는 휴지통으로 보내서 새 이미지가 쓰이게 함
